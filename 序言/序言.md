## 为什么写这本书

2025 年初，你可能在公司里接到一个任务："用大模型做一个智能客服"或者"做一个能自动处理工单的 Agent"。你查了几天文档，写了几百行 Python，调通了 OpenAI API，写了个 ReAct 循环，接了个 RAG，在 demo 演示时效果惊艳——老板当场拍板："下周上线。"

然后噩梦开始了。

上线第一天，Agent 把张三的订单信息发给了李四。第二天，它在无限循环里烧掉了 200 块钱的 token。第三天，它"幻觉"出一个不存在的 API 接口，调了 500 次全部超时。第四天，你凌晨三点被叫起来，因为 Agent 自作主张执行了一条 `rm -rf` 命令。

你困惑了：demo 里明明好好的，为什么一上生产就崩溃？

**因为这个 Agent 从来就不是"一个系统"，它只是"一个 demo 加了一层外壳"。**

这就像你造了一匹很快的马（大模型），给它配了马鞍（框架），然后在一条没有护栏的悬崖边上让它全速奔跑。马没问题，马鞍没问题，问题在于——**你没有给它修路、设护栏、装刹车、配导航**。

2026 年 2 月，HashiCorp 联合创始人 Mitchell Hashimoto 给这套"马之外的工程"起了一个名字：**Harness Engineering（驾驭工程）**。他用一句话定义了它：

> "每当你发现 Agent 犯了一个错，你就花时间在它外面工程化一个方案，让它永远不再犯同样的错误。"

一周后，OpenAI 发表了一篇文章：三个工程师，五个月，用 Codex 生成了约一百万行代码，零行手写。他们 80% 的工作不是调模型，而是**建 Harness**。

这本书，就是教你建 Harness 的。

## 这不是一本什么书

在开始之前，先说清楚这本书**不是**什么：

**这不是一本"零基础入门书"。** 如果你还没用过 OpenAI API、不知道什么是 token、没写过 Python，这本书不适合你。市面上有十几本"AI Agent 从零到一"的书，请先读那些。

**这不是一本"框架教程"。** 你不会在这本书里看到"LangChain 101"或"CrewAI 快速上手"。框架会迭代，但框架背后的工程原理不会。本书讲的是原理，偶尔用框架做例子。

**这不是一本"Prompt 大全"。** Prompt Engineering 是 Agent 工程的地基，但只是地基。这本书的地基在第一章就铺完了，后面 28 章讲的是地基之上的建筑。

**这不是一本"概念科普书"。** 如果你想了解"AI Agent 有哪些类型""多 Agent 协作的未来愿景"，请看行业报告。这本书的每一章都落在"怎么干"上。

## 这本书适合谁

**核心读者**：有 3 年以上软件开发经验的工程师，正在或即将参与 AI Agent 项目，需要从原型走向生产。你可能已经会用 LangChain 搭一个 demo，但你困惑于：为什么 demo 能跑、生产却崩？怎么让 Agent 可靠？怎么控制成本？怎么测试一个"非确定性系统"？

**次级读者**：AI 应用架构师、技术负责人、正在转型 AI 方向的传统软件工程师。

如果你符合以下任意两条，这本书就是为你写的：

- 你写过生产级后端服务，知道"能跑"和"能上线"之间的距离
- 你调过 LLM API，体验过"同一个 prompt 这次对下次错"的绝望
- 你用框架搭过 Agent demo，但不知道怎么把它变成 7×24 小时运行的系统
- 你关心成本、延迟、可靠性，而不是只关心"效果好不好"
- 你想知道 OpenAI、Anthropic、LangChain 的工程师们到底在做什么

## 怎么读这本书

全书 8 篇 29 章，有一个清晰的递进结构。根据你的需求，有三条阅读路线：

**速通路线（2-3 小时）**：读序言 → 第 1 章（Agent 是什么）→ 第 4 章（四大工程范式总览）→ 第 8 章（Harness 工程总览）→ 第 27 章（从零构建 Agent）。这条路线让你在半天内建立完整的心智模型，知道"Agent 工程"的全貌是什么。

**工程深读路线（1-2 周）**：按顺序读第一篇到第四篇。这是理论主线，讲透 Agent 的本质、四大工程范式（Prompt → Context → Loop → Harness）、设计模式。读完这四篇，你能回答"为什么"层面的所有问题。

**实战路线（2-4 周）**：在工程深读路线基础上，加上第三篇（Harness 落地）、第五篇（多 Agent）、第六篇（开源框架解读）、第八篇（实战）。这是实践主线，讲透"怎么做"。读完这条路，你应该能独立设计和构建一个生产级 Agent 系统。

无论走哪条路线，都建议先读第 4 章——四大工程范式总览。它是全书的"地图"，后面所有章节都是地图上的某个区域。

## 关于技术版本

本书基于 2026 年 8 月的技术栈状态编写。关键版本信息：

- **Harness Engineering**：2026 年 2 月由 Mitchell Hashimoto 命名，OpenAI/Anthropic/LangChain 相继采用
- **MCP（Model Context Protocol）**：Anthropic 2024 年 11 月发布，2025 年 12 月捐给 Linux Foundation 旗下 Agentic AI Foundation
- **A2A（Agent-to-Agent Protocol）**：Google 2025 年 4 月发布，2025 年 6 月捐给 Linux Foundation，2026 年 3 月 v1.0
- **OpenAI Codex CLI**：2025 年 4 月开源（Apache 2.0），Rust 构建，2026 年 5 月约 84K GitHub Stars
- **LangGraph**：LangChain 生态的图驱动 Agent 编排框架

技术发展很快，但工程原理不会。即使具体工具版本变了，本书讲的四层工程模型、设计模式、Harness 六大组件这些框架性知识，依然有效。

## 一个比喻贯穿全书

在开始正文之前，我想用一个比喻锚定全书的核心思想：

**Agent 是一匹快马，Harness 是马具。**

大模型是那匹马——速度快、力量大、但有自己的脾气，可能受惊跑偏，可能看见草就停下来吃，可能被路边的什么东西吸引注意力。你不能怪马，马的本性如此。

Harness 是缰绳、马鞍、马蹄铁、护栏、道路——所有让你能**驾驭**这匹马的东西。好的骑手不是换一匹更听话的马，而是给马配一套更好的马具，修一条更安全的路。

> **一个中等水平的模型配上优秀的 Harness，胜过一个顶尖模型配上糟糕的 Harness。**

这不是我的观点，是 2026 年业界用数据验证的共识。LangChain 做了一个实验[^langchain-anatomy]：固定 GPT-5.2-Codex 模型不变，只改 Harness，Agent 基准得分从 52.8% 提升到 66.5%。这个提升幅度，比换一个更贵的模型还大。

这本书的每一章，本质上都在回答同一个问题：**怎么给马配一套好马具？**

准备好了吗？我们出发。
