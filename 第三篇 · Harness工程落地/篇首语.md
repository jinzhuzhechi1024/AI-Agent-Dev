## 第三篇 · Harness 工程落地 —— 扩展机制与安全基石

> 理论到此为止——这一篇展开 Harness 的"How"：沙箱隔离、MCP 协议、Skills 系统、Rule/Hooks、Sub-Agent

---

第二篇建立了四大工程范式的理论框架：Prompt → Context → Loop → Harness，层层嵌套，逐步递进。但理论是地图，不是目的地。知道"Harness 三大支柱"是什么，不等于知道怎么搭一个沙箱；理解"架构约束"的重要性，不等于会写一条 CI 规则。

第三篇是实践主线。我们将用五章篇幅，逐一展开 Harness 六大组件的具体实现——从最底层的沙箱隔离，到最高层的多 Agent 编排。

**第 9 章 沙箱与安全执行**：Agent 要跑代码，但 `rm -rf /` 怎么防？恶意 npm 包怎么拦？这一章讲沙箱的实现方案（macOS Seatbelt / Linux Landlock / Docker / E2B 云沙箱）、权限分级模型、以及"写→跑→看→修"的自我验证循环。

**第 10 章 MCP 协议深度解析**：MCP 是 Anthropic 2024 年 11 月发布的工具调用标准协议，被称为"AI 工具调用的 USB-C"。这一章讲 MCP 的三层架构（Host-Client-Server）、三大原语（Tools/Resources/Prompts）、通信原理（JSON-RPC 2.0），以及从零用 Python 和 TypeScript 各开发一个 MCP Server 的完整实战。

**第 11 章 Skills 系统**：Skills 是"渐进式披露"的载体——不把所有信息塞进上下文，而是按需加载。这一章讲 Skills 的三层加载机制、SKILL.md 标准结构、以及"为什么 Skills 能解决上下文爆炸"的原理。

**第 12 章 Rule 与 Hooks**：Rule 是"写在文件里的行为规范"，Hooks 是"在工具调用前后插入的确定性逻辑"。这一章讲 AGENTS.md 的设计方法论、PreToolUse/PostToolUse Hooks 的工程实现，以及"约束编码化"的实践。

**第 13 章 Sub-Agent**：当任务太复杂，一个 Agent 搞不定时怎么办？派出子 Agent。这一章讲 Sub-Agent 的编排模式（Supervisor / Network / Hierarchical）、上下文隔离的工程实现，以及递归 Agent 的设计。

这五章有一个共同的主线：**把不确定性转化为确定性**。沙箱把"Agent 可能跑危险代码"的不确定性转化为"代码只能在隔离环境跑"的确定性。MCP 把"每个框架自己定义工具格式"的不确定性转化为"统一协议"的确定性。Skills 把"上下文该放什么"的不确定性转化为"按需加载"的确定性。Hooks 把"Agent 可能违反规范"的不确定性转化为"违规即拦截"的确定性。

这就是 Harness 工程的本质——**用工程手段，把模型的不可靠性封装在可靠的系统边界内**。
